# آزمایش کامل محلی بدون حساب بیرونی

این حالت به درخواست کاربر پیش‌فرض است. `LOCAL_SANDBOX=true` و `PAYMENT_MODE=local`؛ در `NODE_ENV=production` آزمایشگاه، صندوق محلی و تصمیم پرداخت محلی از API در دسترس نیستند. هیچ پیامک، ایمیل یا صورتحسابی از شبیه‌ساز به بیرون ارسال نمی‌شود.

## پرداخت و اشتراک

1. با مدیر سازمان وارد `/subscription` شوید و «پرداخت آزمایشی» یک پلن را بزنید.
2. صفحهٔ `/test-payment?id=...` مبلغ ریالی و مدت پلن را نشان می‌دهد. کارت بانکی لازم نیست.
3. «پرداخت موفق آزمایشی» اشتراک همان سازمان را تمدید می‌کند. تکرار یا درخواست هم‌زمان، تمدید دوم ایجاد نمی‌کند.
4. برای آزمون شکست یا انصراف، درخواست جدید بسازید و نتیجهٔ مربوط را انتخاب کنید. اعتبار تغییر نمی‌کند و پرداخت بسته‌شده قابل تبدیل به موفق نیست.
5. سوابق، شناسهٔ `LOCAL` و شمارهٔ پیگیری محلی را نشان می‌دهند؛ این‌ها رسید بانکی نیستند.

برای بازگشت به Sandbox بیرونی زرین‌پال، `PAYMENT_MODE=sandbox` تنظیم و بک‌اند دوباره اجرا شود. این تغییر برای آزمون محلی فعلی لازم نیست.

## ایمیل، بازیابی و دعوت

- در `/profile` «ساخت پیوند تأیید ایمیل» و سپس «صندوق ایمیل آزمایشی» را بزنید. پیوند را باز و تأیید کنید. استفادهٔ دوم و پیوند منقضی رد می‌شود.
- درخواست بازیابی از `/forgot-password` پیام محلی می‌سازد. مدیر کل از لینک صندوق در `/platform` می‌تواند پیوند بازیابی حساب آزمایشی را باز کند. با تغییر رمز، نشست‌های قبلی لغو می‌شوند.
- دعوت را از پروفایل مدیر سازمان بسازید. پذیرش نیازمند ورود با همان ایمیل دعوت‌شده است. این نسخه برای دعوت حساب موجود طراحی شده؛ کاربر جدید ابتدا حساب ایجاد می‌کند.
- اعضا فقط پیام‌های ایمیل خود را می‌بینند؛ مدیر کل در آزمایشگاه محلی همهٔ پیام‌ها را می‌بیند. پیوندها حاوی توکن حساس‌اند و نباید منتشر شوند.

## مؤدیان و پیامک

1. در `/integrations` تنظیم اتصال را باز کنید؛ محیط «شبیه‌ساز کامل محلی» و وضعیت فعال را ذخیره کنید.
2. برای مؤدیان یک فاکتور فروش قطعی انتخاب کنید. در شبیه‌ساز به شناسهٔ مالیاتی، گواهی یا کلید واقعی نیاز نیست؛ این تسهیل فقط در حالت محلی است.
3. برای پیامک شمارهٔ آزمایشی با قالب `09xxxxxxxxx` و متن وارد کنید.
4. نتیجه را انتخاب کنید: موفق، رد درخواست، خطای موقت و سپس موفق، یا بی‌پاسخ و نیازمند بررسی.
5. صف خودکار به‌روز می‌شود. وضعیت‌های `LOCAL_SUCCESS` و `LOCAL_FAILED` فقط نتیجهٔ شبیه‌سازند. سناریوی خطای موقت در تلاش دوم موفق می‌شود؛ بی‌پاسخ پس از سه تلاش به بررسی دستی می‌رود. «تلاش مجدد» در حالت محلی، بازیابی به سناریوی موفق را آزمایش می‌کند.

پیش‌نمایش dry-run و اتصال Sandbox رسمی مؤدیان همچنان گزینه‌های جدا هستند. ارسال رسمی همچنان تمام اطلاعات و کنترل‌های قبلی را لازم دارد.

## جدول‌ها و ظرفیت

فهرست رکوردهای حسابداری جست‌وجو، فیلتر ستون، مرتب‌سازی عددی و صفحه‌بندی را در PostgreSQL انجام می‌دهد. جست‌وجو «ی/ي»، «ک/ك»، ارقام فارسی/عربی/لاتین و تاریخ شمسی کامل یا سال/ماه را پشتیبانی می‌کند. نام رکوردهای مرجع نیز قابل جست‌وجو است. انتخاب ستون، خروجی Excel نتایج همهٔ صفحات و دکمهٔ «چاپ همهٔ نتایج» حفظ شده‌اند. برای چاپ کامل فهرست از این دکمه استفاده کنید؛ چاپ مستقیم مرورگر بدون آماده‌سازی فقط دادهٔ بارگذاری‌شده را دارد.

سنجش در دیتابیس مجزا با ۵۰۰۰ رکورد، ۱۰ درخواست هم‌زمان و ۲۰ درخواست انجام می‌شود. گزارش واقعی در `artifacts/backend-review/load-report.json` است. این سنجش فهرست/جست‌وجو است؛ آزمون جامع ظرفیت همهٔ گزارش‌ها یا تضمین کارایی تولید نیست. lookupهای اولیه و بعضی گزارش‌ها هنوز کل دادهٔ مرتبط را می‌خوانند.

## استهلاک و حقوق

بازهٔ استهلاک به ماه شمسی است: تاریخ سند، ماه پایان بازه و «تعداد ماه»، تعداد ماه‌های منتهی به آن را تعیین می‌کند. دورهٔ پیش از خرید و هم‌پوشان با استهلاک قطعی قبلی رد می‌شود. این روش کنترل دوره است، نه تأیید جداول استهلاک مالیاتی.

محاسبات حقوق را با قواعد نمونه پیش‌نمایش کنید. برای ثبت قطعی، مدیر باید نسخهٔ قواعد معتبر برای تاریخ را تأیید کند. با انتخاب کاربر، فعلاً محاسبات و خروجی آزمایشی کافی است؛ قواعد نمونه جایگزین بخشنامهٔ قانونی نیستند.

صفحهٔ `/payroll-exports` سه نمای «خلاصه حقوق»، «لیست بیمه» و «لیست مالیات» دارد. هر نما جست‌وجوی ستون، فیلتر ماه، Excel و چاپ دارد. مبالغ به ریال تبدیل می‌شوند؛ فقط فیش‌های قطعیِ برگشت‌نخورده در خروجی هستند. نام و شناسهٔ کارمند در فیش‌های جدید هنگام ثبت قطعی ذخیره می‌شود تا ویرایش بعدی پرونده، خروجی تاریخی را تغییر ندهد.

`npm run db:demo` علاوه بر داده‌های قبلی، یک کارمند و فیش مشخصِ ساختگی با قواعد «آزمون محلی» می‌سازد. این seed فقط در محیط محلی مجاز است؛ شناسه‌ها واقعی نیستند و اجرای دوباره فیش تکراری نمی‌سازد. برای تست خروجی با `demo@taraz.local` وارد شوید و شرکت اول و سال جاری را انتخاب کنید.

## اجرا و تست

```bash
npm run db:start
npm run db:migrate
npm run db:generate --prefix backend
npm run backend:build
npm run local:start
```

برای تست کامل پس از تغییر کد:

```bash
npm run build
npm run test:full
```

دیتابیس تست از دیتابیس اصلی جداست و برای بررسی حفظ می‌شود. رمزها و توکن‌های تست وارد گزارش عمومی یا Git نمی‌شوند.
