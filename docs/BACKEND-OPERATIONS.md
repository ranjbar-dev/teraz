# راهنمای بک‌اند تراز

این سند وضعیت واقعی نسخهٔ محلی را شرح می‌دهد. طرح اولیه در BACKEND-IMPLEMENTATION.md تضمین پیاده‌سازی تمام پیشنهادها نیست.

ادامهٔ کار با انتخاب کاربر روی **محیط آزمایشی محلی** انجام شده است. پیش‌فرض پرداخت محلی، صندوق ایمیل مرورگری، تأیید ایمیل یک‌بارمصرف و سناریوهای شبیه‌ساز مؤدیان/پیامک در [LOCAL-TESTING.md](LOCAL-TESTING.md) شرح داده شده‌اند. این شبیه‌سازها در production از API قابل استفاده نیستند.

## معماری و اجرا

مرورگر به Route Handler هم‌مبدأ Next.js در `/api` درخواست می‌دهد. این مسیر با `BACKEND_URL` ثابت به NestJS روی 127.0.0.1:4000 متصل است. Nest از Prisma 7 و adapter-pg به PostgreSQL 18.6 روی 127.0.0.1:55432 متصل می‌شود. دیتابیس اصلی `taraz` و نقش برنامه `taraz_app` است. سرور و دیتابیس محلی به Docker یا سرویس Windows وابسته نیستند.

`npm run local:setup` نصب و migration و seed و build بک‌اند را انجام می‌دهد. `npm run db:demo` دادهٔ فارسی نمایشی را داخل دیتابیس واقعی می‌سازد. `local:start` پردازش‌های پس‌زمینهٔ مخفی را راه می‌اندازد؛ خروجی در `.runtime/api.log` و `.runtime/web.log` و شناسهٔ پردازش‌های تحت مدیریت در `.runtime/processes.json` ذخیره می‌شود. اگر پورت فرانت‌اند از قبل فعال باشد، اسکریپت آن پردازش را تصاحب یا متوقف نمی‌کند.

اسکریپت‌ها:

| فایل | مسئولیت |
| --- | --- |
| scripts/local-db.mjs | دریافت ZIP رسمی، ساخت کاربر و دیتابیس، start/stop/status |
| scripts/local-app.mjs | اجرای محلی API و Next، نگهداری PID و log |
| scripts/backup.mjs | dump، پیوست‌ها و بازیابی در دیتابیس تازه |
| scripts/test-backend.mjs | دیتابیس و API مجزای تست، اجرای تست و مرورگر |
| backend/src/seed.ts | پلن‌ها و مدیر کل اولیه؛ بدون بازنویسی رمز موجود |
| backend/src/seed-demo.ts | سازمان و دادهٔ نمایشی مستقل |

رمزها در `.runtime/local-credentials.json` و تنظیم اتصال در `backend/.env` تولید می‌شوند. `.runtime` و `.env` در Git نیستند. متغیر `ENCRYPTION_KEY` باید ۳۲ بایت hex باشد و برای خواندن تنظیمات رمز‌شده پایدار بماند. تغییر آن بدون مهاجرت رمزنگاری، تنظیمات قبلی را غیرقابل خواندن می‌کند. برای محیط HTTPS، `COOKIE_SECURE=true` و `WEB_ORIGIN` دقیق تنظیم شود.

## قرارداد API

تاریخ‌ها ISO میلادی `YYYY-MM-DD` و نمایش رابط شمسی است. مقدار پول/تعداد Decimal در پاسخ رشته است؛ از تبدیل آن به Number برای محاسبات مالی پرهیز کنید. عملیات چندرکوردی داخل تراکنش Serializable با قفل سازمانی و retry محدود اجرا می‌شود.

| مسیر | کاربرد |
| --- | --- |
| POST auth/register, auth/login | ایجاد سازمان آزمایشی یا ورود |
| GET auth/me / DELETE auth | هویت فعلی یا خروج |
| POST auth/switch, auth/password | تغییر سازمان یا رمز |
| POST auth/forgot, auth/reset | لینک یک‌بارمصرف و بازیابی رمز |
| POST auth/request-verification, auth/verify-email | صدور و مصرف پیوند تأیید ایمیل |
| GET local-mail | صندوق محلی؛ فقط گیرنده یا مدیر کل |
| POST invitations / invitations/accept | دعوت و پذیرش با حساب منطبق |
| GET bootstrap | محدوده، نقش، شرکت/شعب/دوره و lookupها |
| GET/POST {module} | فهرست یا ایجاد یکی از ۳۱ ماژول |
| GET/PATCH/DELETE {module}/{id} | جزئیات، ویرایش مجاز یا حذف مجاز |
| POST {module}/{id}/post, reverse, convert | قطعی‌سازی، برگشت یا تبدیل پیش‌فاکتور |
| GET dashboard / reports/{key} | شاخص‌ها و ۱۰ گزارش |
| GET/PATCH settings / GET activity | تنظیمات شرکت و ممیزی |
| GET/POST payroll-rules / POST payroll-calculate | قواعد و پیش‌محاسبهٔ سرور |
| GET payroll-exports | فیش‌های قطعی برای خروجی آزمایشی حقوق، بیمه و مالیات؛ فیلتر ماه/تاریخ |
| POST period-close | اختتامیه و آماده‌کردن سال بعد |
| GET/POST attachments / GET/DELETE attachments/{id} | فایل خصوصی |
| GET subscription / POST billing/checkout | اشتراک و هدایت به درگاه |
| GET/POST billing/local/{id} | مشاهده و تعیین نتیجهٔ پرداخت محلی همان سازمان |
| GET platform | نمای کلی مدیر کل، سازمان‌ها، پلن‌ها و ممیزی |
| POST/PATCH platform/organizations[/{id}] | ایجاد و مدیریت سازمان/اشتراک |
| POST/PATCH platform/plans[/{id}] | تعریف و ویرایش پلن |
| GET integrations / PATCH integrations/{provider} | تنظیم اتصال، بدون افشای کلید ذخیره‌شده |
| POST integrations/{provider} | صف درخواست آزمایشی |

همهٔ مسیرها زیر `/api` هستند. OpenAPI در `/docs` قرارداد پایهٔ ماژول‌ها را ارائه می‌کند؛ برای payload عملیات اختصاصی به فرم مربوط و سرویس آن مراجعه کنید. مسیر دقیق callback و job در `main.ts` تعریف شده است.

پارامترهای `companyId`, `branchId`, `yearId` صرفاً محدودهٔ درخواستی‌اند؛ سرور مجوز و تعلق آن‌ها به سازمان نشست را بررسی می‌کند. `branchId=all` خواندن همهٔ شعب مجاز شرکت است. گزارش‌ها `from/to` و دفتر کل `accountId` دارند. PATCH رکورد به `version` آخر نیاز دارد و نسخهٔ کهنه 409 می‌گیرد. درخواست ایجاد می‌تواند `Idempotency-Key` داشته باشد؛ تکرار با payload متفاوت 409 است. فایل حداکثر ۵MB و PDF/JPEG/PNG با بررسی امضای فایل است.

## قواعد حسابداری

- دفتر و آرتیکل قطعی، گردش موجودی و ممیزی با trigger در برابر ویرایش/حذف برنامه محافظت می‌شوند. trigger تعویقی توازن و حداقل دو آرتیکل دفتر را پیش از commit بررسی می‌کند. مالک دیتابیس همچنان قدرت مدیریتی دارد؛ این سازوکار جایگزین جداسازی نقش مهاجرت در تولید نیست.
- اسناد قطعی بازنویسی نمی‌شوند. برگشت با تاریخ و دلیل، ثبت معکوس و گردش معکوس می‌سازد؛ وابستگی تسویه/موجودی می‌تواند برگشت را رد کند.
- موجودی میانگین موزون و هزینهٔ فروش هنگام قطعی‌سازی ثبت می‌شود. فروش بیش از موجودی، ثبت قبل از آخرین گردش کالا و برگشت فاقد موجودی رد می‌شوند.
- نرخ ارز و اطلاعات فروشنده/طرف حساب/اقلام فاکتور در سند قطعی snapshot می‌شوند. تخفیف کل بین اقلام توزیع و اختلاف گردکردن تنظیم می‌شود. برگشت به اصل فاکتور متصل و مقدار آن محدود به مقدار قابل برگشت است.
- دریافت/پرداخت تخصیص و ماندهٔ فاکتور را نگه می‌دارند. API تخصیص چندگانه را پشتیبانی می‌کند؛ فرم فعلی یک فاکتور را انتخاب می‌کند. اختلاف تسعیر تحقق‌یافته دفتر دارد. انتقال بانکی میان حساب‌های هم‌ارز است.
- چک در جریان ابتدا به حساب واسط چک ثبت و در وصول به بانک منتقل می‌شود. گردش کامل ظهرنویسی/واگذاری و رسیدگی حقوقی چک برگشتی پیاده نشده است.
- استهلاک خط مستقیم و محدود به ارزش قابل استهلاک است. فروش/اسقاط خودکار دارایی و همهٔ روش‌ها و جداول مالیاتی دارایی پیاده نشده‌اند؛ اصلاح مالی آن‌ها فعلاً سند دستی می‌خواهد.
- تولید مواد فرمول را مصرف و محصول را با هزینهٔ مواد و سربار وارد می‌کند. ظرفیت‌سنجی کارگاه و MRP در دامنهٔ فعلی نیست.
- اختتامیه حساب‌های موقت را به سود انباشته می‌بندد و سال را قفل می‌کند. گزارش دائمی مانده‌ها را تجمعی می‌خواند؛ افتتاحیهٔ تکراری ساخته نمی‌شود. سود تاریخی از آرتیکل اختتامیه اثر نمی‌گیرد. بازگشایی سال فعلاً مجاز نیست.

## حقوق، بیمه و مالیات ایران

قواعد با تاریخ اعتبار، منبع و تأیید مدیر نسخه‌دار می‌شوند. مقدار نمونهٔ ۱۴۰۵ به‌صورت **تأییدنشده** عرضه می‌شود و برای قطعی‌سازی باید نسخهٔ تأییدشدهٔ معتبر وجود داشته باشد. تأیید مدیر به معنای تأیید قانونی توسط نرم‌افزار نیست.

محاسبه شامل روز کار، پایه/مزایا، اضافه‌کاری، معافیت‌های ورودی، سهم‌های بیمه، سقف بیمه، پله‌های مالیات و خالص است؛ ارقام قانونی به ریال و مبنای شرکت ریال/تومان تبدیل می‌شوند. مقدار بیمه و مالیات هنگام ثبت قطعی دوباره روی سرور محاسبه و snapshot می‌شود.

با انتخاب کاربر، **محاسبات و خروجی آزمایشی برای دامنهٔ فعلی کافی است**. صفحهٔ `/payroll-exports` خلاصه حقوق، لیست بیمه و مالیات را از snapshot فیش قطعی می‌سازد و Excel/چاپ می‌دهد؛ مبالغ ریالی و عنوان آزمایشی هستند.

**کار باقی‌مانده برای انطباق کامل عملیاتی:** تأیید تمام مقادیر و فرمول‌ها با بخشنامهٔ رسمی سال مربوط، مالیات تجمیعی سالانه و چندکارفرمایی، عیدی/سنوات/مرخصی/مأموریت و طبقه‌بندی اقلام، موارد خاص معافیت، خروجی رسمی قابل بارگذاری بیمه و مالیات و آزمون تطبیقی با حسابدار حقوق. محاسبهٔ فعلی ماهانه است. این بخش را فعلاً جایگزین محاسبهٔ قانونی تأییدشده نکنید.

حداقل مزد روزانهٔ نمونه ۵٬۵۴۱٬۸۵۰ ریال از اطلاع‌رسانی رسمی تأمین اجتماعی برای ۱۴۰۵ بررسی شد؛ این بررسی به‌تنهایی بقیهٔ ضرایب و پله‌ها را تأیید نمی‌کند.

## اتصال‌های بیرونی

### زرین‌پال

درخواست و verify به `sandbox.zarinpal.com/pg/v4/payment` و هدایت به StartPay است. مبلغ اشتراک ریال است؛ شناسهٔ تست UUID است. وضعیت callback به‌تنهایی معتبر نیست و verify سرور ملاک است. پرداخت موفق با تراکنش و وضعیت ذخیره‌شده تنها یک بار اشتراک را تمدید می‌کند، حتی در callback هم‌زمان یا کد 101.

درخواست واقعی Sandbox پاسخ 100 و Authority آزمایشی داد. verify و رقابت callback در آزمون قرارداد پوشش دارند؛ مسیر پرداخت تعاملی و verify واقعی نهایی هنوز با ارائه‌دهنده اجرا نشده است.

### سامانهٔ مؤدیان

کلاینت بر اساس سند فنی RC_TICS.IS_v1.4 بهمن ۱۴۰۳ نوشته شده: nonce، امضای RS256 با x5c و sigT، رمز JWE با RSA-OAEP-256/A256GCM، کلید سرور، ارسال، استعلام UID و صف پایدار با lease و retry. تست JWE واقعاً رمزگشایی را بررسی می‌کند. در پاسخ نامشخص، ابتدا استعلام انجام می‌شود؛ پس از ابهام پایدار REVIEW_REQUIRED می‌گیرد و موفقیت فرض نمی‌شود.

پیش‌فرض dry-run است. ارسال نیازمند گواهی معتبر، کلید منطبق، شناسهٔ حافظه و اقتصادی و شناسه/واحد مالیاتی کالا است. `MODIAN_BASE_URL` باید نشانی HTTPS رسمی محیط sandbox باشد و پس از تأیید مستند، `MODIAN_SANDBOX_VERIFIED=true` شود. نشانی پیشنهادی داخل کد تضمین فعال‌بودن محیط نیست. نسخهٔ فعلی سند رسمی باید پیش از اتصال کنترل شود.

پشتیبانی فعلی الگوی پایهٔ ۱ است. شمارهٔ منحصر‌به‌فرد مالیاتی ۲۲کاراکتری از ورودی دریافت می‌شود؛ تولید رسمی شماره و الگوریتم کنترل آن، همهٔ الگوها، اعتبارسنجی زنجیرهٔ اعتماد امضای پاسخ نهایی و آزمون پذیرش واقعی هنوز تکمیل نشده‌اند. صف DRY_RUN به معنای پذیرش سازمان مالیاتی نیست.

### sms.ir و ایمیل

`SmsIrClient` مسیر رسمی `/v1/send/verify` با `X-API-KEY` و templateId/parameters را اجرا می‌کند؛ موفقیت، خطای ارائه‌دهنده و ورودی نامعتبر تست شده‌اند. برای جلوگیری از اشتباه گرفتن ارسال واقعی با sandbox، worker برنامه فعلاً فقط dry-run محلی دارد. محیط مستقل آزمایشی رسمی تأیید نشده و ارسال واقعی نیازمند انتخاب صریح آن حالت و حساب معتبر است.

ایمیل دعوت، بازیابی و تأیید نشانی در جدول LocalMail و `.runtime/mail` ذخیره و از `/local-lab` مشاهده می‌شود؛ ارسال بیرونی انجام نمی‌شود. تأیید یک‌بارمصرف نشانی پیاده و تست شده است. در production بدون ارائه‌دهندهٔ ایمیل خطای صریح داده می‌شود. الزامی‌کردن تأیید مالکیت برای ثبت‌نام عمومی، ارسال واقعی و مدیریت خطا/بازگشت ایمیل هنوز لازم است.

## امنیت، ظرفیت و انتشار عمومی

نشست تصادفی و hash‌شده، کوکی HttpOnly/SameSite، scrypt رمز، محدودیت ورود، کنترل Origin، Helmet، رمزنگاری تنظیمات، عضویت/محدودهٔ شرکت، ارجاع‌های هم‌شرکت و ممیزی پیاده شده‌اند. SUPER_ADMIN جدا از نقش سازمان است. SQL RLS وجود ندارد و جداسازی بر سرویس و کلیدهای رابطه‌ای تکیه دارد. تست عبور از مرز سازمان و نقش موجود است.

فهرست رکوردها اکنون فیلتر، جست‌وجوی فارسی و تاریخ شمسی، مرتب‌سازی و صفحه‌بندی SQL دارد؛ مانده‌های نمایش به‌صورت گروهی خوانده می‌شوند. جدول‌های حسابداری فقط صفحهٔ جاری را دریافت می‌کنند و Excel/چاپ کامل، نتایج را صفحه‌به‌صفحه می‌گیرد. سنجش ۵۰۰۰ رکورد با ۱۰ درخواست هم‌زمان اجرا شده و گزارش آن در `artifacts/backend-review/load-report.json` است. bootstrap هنوز همهٔ lookupهای شرکت و بعضی گزارش‌ها همهٔ آرتیکل‌های بازه را می‌خوانند؛ سنجش فعلی تضمین ظرفیت تمام عملیات در تولید نیست.

برای انتشار عمومی علاوه بر موارد قانونی و اتصال‌های فوق، HTTPS، MFA مدیر کل، تأیید ایمیل، نقش جداگانهٔ migration، نگهداری و بازیابی خارج از دستگاه، پایش، آزمون بار و بازبینی امنیت مستقل لازم است. پیکربندی فعلی اجرای توسعهٔ محلی است.

## پشتیبان و بازیابی

`npm run db:backup` با pg_dump قالب custom و بدون مالک، دیتابیس و کپی پیوست‌ها و manifest می‌سازد. `npm run db:restore -- .runtime/backups/NAME` یک دیتابیس تازه با نام `taraz_restore_*` ایجاد می‌کند؛ دیتابیس جاری پاک یا جایگزین نمی‌شود. پس از بررسی دستی، DATABASE_URL را می‌توان به دیتابیس بازیابی‌شده تغییر داد و پیوست‌ها را از پوشهٔ پشتیبان برگرداند.

ایجاد backup و restore روی دستگاه آزمایش شدند. dump و کپی فایل‌ها یک snapshot اتمیک مشترک نیستند؛ برای پشتیبان سازگار، نوشتن برنامه را هنگام backup متوقف کنید. کلید رمزنگاری در backup نیست و باید جداگانه امن نگه‌داری شود. نگه‌داشتن backup فقط در همان دستگاه راهکار بازیابی حادثه نیست.

## شواهد آزمون و منابع

تست واقعی HTTP/PostgreSQL شامل توازن، تغییرناپذیری در SQL، رقابت فروش بیش از موجودی، نسخهٔ کهنه، تکرارپذیری، برگشت، تسویه، حقوق، اشتراک، نقش، فایل، رمزنگاری و اختتامیه است. تست مرورگر مسیرهای تمام ماژول‌ها، گزارش‌ها، تنظیمات و احراز هویت و ساخت سازمان/پلن را بررسی می‌کند. نتیجه و تصاویر در `artifacts/backend-review` نگه‌داری می‌شوند. تست محلی قرارداد ارائه‌دهنده جایگزین آزمون رسمی پذیرش نیست.
