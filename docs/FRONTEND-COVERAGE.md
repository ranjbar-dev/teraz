# گزارش پوشش و بازبینی رابط تراز

> این گزارش به بازبینی فرانت‌اند با API نمایشی قبلی مربوط است. برای نسخهٔ متصل به PostgreSQL، نتیجهٔ جدید در `artifacts/backend-review/browser-report.json` و شرح دامنه در [BACKEND-OPERATIONS.md](BACKEND-OPERATIONS.md) است.

## دامنهٔ تحویل

این گزارش مربوط به رابط فارسی حسابداری عمومی با API داخلی آزمایشی است. ۳۱ ماژول تعریف‌شده، هر کدام چهار مسیر فهرست، ایجاد، جزئیات و ویرایش دارند؛ به‌علاوهٔ ۱۰ گزارش و صفحه‌های ورود، داشبورد، کتابخانهٔ گزارش‌ها، تنظیمات، فعالیت‌ها و راهنما. جمع این الگوهای مسیر ۱۴۰ است. صفحهٔ خطا و مسیر ناموجود نیز وجود دارد.

«پوشش کامل» در این گزارش یعنی مسیرهای تعریف‌شدهٔ این نسخه و تعاملات مشترک آن ساخته شده‌اند و صفحهٔ placeholder ندارند. این عبارت به معنی تضمین نبود هر باگ احتمالی یا پیاده‌سازی تمام قابلیت‌های هر محصول حسابداری بازار نیست. مرزهای backend و قابلیت‌های خارج از این نسخه در انتهای این سند و [نقشهٔ بک‌اند](BACKEND-IMPLEMENTATION.md) مشخص شده‌اند.

## گزارش‌ها و صفحه‌های مکمل

گزارش‌های `/reports/profit-loss`، `balance-sheet`، `trial-balance`، `journal`، `ledger`، `receivables`، `inventory`، `cashflow`، `tax` و `project-profit` از API دادهٔ محاسبه‌شده می‌گیرند. تست مرورگر نمایش نتیجهٔ هر ۱۰ گزارش را بررسی می‌کند؛ تراز آزمایشی و ترازنامه در سناریوی نمونه از نظر توازن نیز بررسی می‌شوند.

داشبورد، فهرست فروش، اشخاص، فرم فروش، کتابخانهٔ گزارش، دفتر کل، تنظیمات و راهنما به عنوان هشت خانوادهٔ نمایشی در عرض‌های ۱۴۴۰ و ۳۹۰ تصویربرداری شدند. ورود هم تصویر مستقل دارد. بررسی عرض ۳۶۰ شامل تمام ۳۱ فهرست و ۳۱ فرم ایجاد است؛ آزمون یکپارچه مسیرهای اصلی را در عرض‌های ۳۶۰، ۳۹۰ و ۷۶۸ نیز بررسی می‌کند.

## اصلاحات این بازبینی

- یکدست شدن فاصله‌ها، اندازهٔ متن، کنتراست، رنگ‌های وضعیت، دکمه‌ها، فیلدها، سربرگ، منو و صفحات چاپ؛ حفظ تم روشن سبز و Vazirmatn محلی.
- جایگزینی تمام ۱۵ محل قبلی `select` با `SearchSelect` مشترک و استفاده از همان کامپوننت برای تغییر وضعیت سند.
- جست‌وجوی نام و کد با یکسان‌سازی اعداد فارسی/عربی/لاتین و حروف ی/ک؛ کنترل با Arrow، Home، End، Enter و Escape.
- نمایش فهرست انتخاب در portal تا در جدول و فرم بریده نشود؛ گزینهٔ انتخاب‌شده، حالت غیرفعال، نتیجهٔ خالی و اعتبارسنجی فیلد ضروری.
- هماهنگی انتخاب ماه و سال تقویم با popup جدید و بازگشت فوکوس به کنترل پس از بستن فهرست.
- نمایش فیلترهای فعال جدول، حذف مستقل آن‌ها، دسترسی به جزئیات از ستون اول و مرتب‌سازی دارای `aria-sort`.
- حذف انتخاب‌های نامعتبر جدول بعد از تغییر فیلتر/داده، بستن فهرست ستون‌ها با Escape یا کلیک بیرون و اصلاح صفحه‌بندی در موبایل باریک.
- حفاظت از تغییرات ذخیره‌نشدهٔ فرم و تنظیمات در لینک‌های داخلی، تغییر شرکت/شعبه/سال و خروج از حساب؛ هشدار مرورگر برای reload/بستن صفحه.
- پیام مناسب برای رکورد ناموجود در ویرایش و برای سال مالی بسته؛ حفظ گزینهٔ قدیمیِ غیرفعال برای نمایش فرم ویرایش.
- جلوگیری از بازنویسی bootstrap جدید توسط پاسخ قدیمیِ تغییر شرکت و پیام فارسی برای خطای ارتباط یا پاسخ ناخوانا.
- پاک‌سازی importهای بدون استفاده؛ عدم وجود `<select>` بومی در DOM مسیرهای ماژول آزموده‌شده.

حفاظت خروج، ذخیرهٔ خودکار draft نیست. دکمهٔ Back/Forward خود مرورگر و بازیابی بعد از بسته شدن ناگهانی تب، تضمین بازیابی متن ندارند؛ در صورت نیاز باید ذخیرهٔ پیش‌نویس سمت سرور یا بازیابی محلی به عنوان قابلیت مستقل اضافه شود.

## آزمون‌ها و شواهد

نتیجهٔ نهایی این بازبینی: build و TypeScript موفق، ۶ تست دامنه موفق، **۳۶۰ بررسی یکپارچه موفق**، صفر بیرون‌زدگی در ۶۲ مسیر فهرست/ایجاد در عرض ۳۶۰ و صفر خطای runtime در بررسی تصویری. smoke تکمیلی نیز موفق بود و چاپ ۲۹۲ ردیف گزارش را در برابر صفحه‌بندی معمول بررسی کرد. این بررسی‌ها با Edge روی Windows انجام شده‌اند؛ Safari و Firefox در این اجرا تست نشده‌اند.

| بررسی                     | فرمان/فایل                                           | چیزی که بررسی می‌کند                                                         |
| ------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------- |
| TypeScript                | `npm run typecheck`                                  | سازگاری تایپ‌ها                                                              |
| پاکیزگی تایپ              | `tsc --noEmit --noUnusedLocals --noUnusedParameters` | import و متغیر بدون استفاده                                                  |
| ساخت production           | `npm run build`                                      | کامپایل Next و تولید مسیرها                                                  |
| ۶ آزمون دامنه             | `npm test`                                           | تخفیف/مالیات، جداسازی scope، افتتاحیه، انتقال بین شعب و توازن فروش/لغو       |
| API و مرورگر              | `npm run test:e2e`                                   | ۳۱ ماژول، ۱۰ گزارش، CRUD شخص، فروش/تسویه، مجوز، موجودی، XLSX و کنترل‌های فرم |
| تمام فهرست/فرم‌های موبایل | `node tests/responsive-audit.mjs`                    | بیرون‌زدگی صفحه در عرض ۳۶۰                                                   |
| تصاویر نهایی              | `node tests/review-ui.mjs`                           | خانواده‌های نمایشی دسکتاپ و موبایل، عدم select بومی و خطای runtime           |
| smoke تکمیلی              | `node tests/final-smoke.mjs`                         | ورود، نرخ ارز، تقویم موبایل، چاپ تمام ردیف‌ها و موجودی شعبه                  |

آزمون یکپارچه سرور production را روی ۳۱۰۰ با پوشهٔ مستقل `.data-test/{runId}` اجرا می‌کند. آزمون‌های تصویری و responsive به dev روی ۳۰۰۰ متصل‌اند و سند مالی ایجاد/ویرایش نمی‌کنند. برای اجرای مرورگر، Microsoft Edge و وابستگی‌های package-lock لازم‌اند.

نتیجهٔ ماشینی نهایی در [test-result.json](../artifacts/review/test-result.json)، پوشش مسیرها در [coverage.json](../artifacts/review/coverage.json) و نتیجهٔ عرض ۳۶۰ در [responsive-audit.json](../artifacts/review/responsive-audit.json) ذخیره می‌شود. این فایل‌ها نتیجهٔ آخرین اجرای موفق مربوط را نشان می‌دهند؛ جای پوشش صددرصدی منطق تجاری نیستند.

## مرز استفادهٔ فعلی

داده‌ها dummy هستند و در JSON محلی نگه‌داری می‌شوند. نرخ‌ها، حقوق، استهلاک و بهای کالا برای تست تعاملات‌اند. اتصال بانکی/مالیاتی، ارسال اعلان، پیوست، import، تلفیق شرکت‌ها، دفتر غیرقابل‌تغییر، بستن خودکار سال و کنترل هم‌زمانی دیتابیس در این نسخه وجود ندارند. صفحه‌های مربوط به فرآیندهای جدید باید همراه بک‌اند آن‌ها اضافه یا گسترش داده شوند.

مخزن محلی ابتدا روی شاخهٔ `main` با commit پایهٔ `1c8a958` ایجاد شد. تغییرات این بازبینی و مستندات در commit جداگانه نگه‌داری می‌شوند. remote ساخته نشده و داده‌های `.data`، فایل‌های محیطی، dependencyها و خروجی build وارد Git نمی‌شوند.
