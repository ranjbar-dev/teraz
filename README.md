# تراز — رابط حسابداری و مدیریت کسب‌وکار

رابط فارسی راست‌به‌چپ، تم روشن سبز و فونت محلی **Vazirmatn**، با **Next.js 16.3.4**، **React 19** و **Tailwind CSS 4.3.3**. فونت به اتصال خارجی وابسته نیست. نسخه‌های دقیق وابستگی‌ها در `package.json` و `package-lock.json` ثبت شده‌اند.

## اجرا

مستندات تحویل: [نقشهٔ پیاده‌سازی بک‌اند](docs/BACKEND-IMPLEMENTATION.md) و [گزارش پوشش صفحات و بازبینی UI/UX](docs/FRONTEND-COVERAGE.md).

به Node.js نسخهٔ ۲۴ یا بالاتر نیاز دارید.

```bash
npm install
npm run dev
```

برنامه در [localhost:3000](http://localhost:3000) اجرا می‌شود.

```bash
npm run build
npm start
```

## ورود آزمایشی

| نقش       | ایمیل                  | رمز عبور     |
| --------- | ---------------------- | ------------ |
| مدیر      | `admin@taraz.app`      | `Taraz1405!` |
| حسابدار   | `accountant@taraz.app` | `Taraz1405!` |
| مشاهده‌گر | `viewer@taraz.app`     | `Taraz1405!` |

در صفحهٔ ورود، انتخاب نقش اطلاعات مربوط به همان کاربر را پر می‌کند. نقش مدیر به تمام بخش‌ها دسترسی دارد. حسابدار اجازهٔ عملیات مالی دارد؛ مشاهده‌گر فقط می‌تواند داده‌ها و گزارش‌ها را ببیند و خروجی بگیرد. محدودیت‌های نوشتن در API نیز بررسی می‌شوند. نشست ورود با کوکی HttpOnly و رمزهای آزمایشی با scrypt ذخیره می‌شوند.

## صفحه‌ها و امکانات

۳۱ ماژول دارای صفحهٔ مستقل فهرست، ایجاد، جزئیات و ویرایش هستند:

- اشخاص و طرف حساب‌ها
- کالاها و خدمات، انبارها، رسید و حواله و انتقال موجودی
- پیش‌فاکتور، فروش، خرید، برگشت از فروش و خرید
- بانک، صندوق و تنخواه، دریافت، پرداخت، انتقال وجه و چک‌ها
- هزینه‌ها، سایر درآمدها، کدینگ حساب‌ها و اسناد دوطرفه
- کارکنان، حقوق و فیش‌های حقوقی
- دارایی ثابت و استهلاک خط مستقیم
- فرمول ساخت و سفارش تولید
- پروژه‌ها و هزینه و درآمد پروژه
- شرکت‌ها، شعبه‌ها، سال مالی، ارزها و کاربران

همچنین داشبورد، تنظیمات، راهنما، تاریخچهٔ فعالیت‌ها و ۱۰ گزارش مالی پیاده‌سازی شده‌اند: سود و زیان، ترازنامه، تراز آزمایشی، روزنامه، کل، بدهکاران و بستانکاران، موجودی، جریان نقدی، مالیات و سودآوری پروژه.

جدول‌ها جست‌وجوی عمومی و مستقل برای ستون‌ها، مرتب‌سازی، انتخاب ستون، صفحه‌بندی، انتخاب ردیف و خروجی واقعی `.xlsx` دارند. جست‌وجو اعداد فارسی و لاتین را یکسان می‌شناسد. خروجی Excel شامل تمام نتایج فیلترشده یا ردیف‌های انتخاب‌شده است. هنگام چاپ گزارش، تمام نتایج فیلترشده چاپ می‌شوند، نه فقط صفحهٔ جاری جدول. چاپ اسناد و ذخیره به PDF از پنجرهٔ چاپ مرورگر در دسترس است.

تمام فهرست‌های انتخاب از کامپوننت جست‌وجودار مشترک استفاده می‌کنند: شرکت، شعبه، سال مالی، گزینه‌های فرم، کالا و حساب هر ردیف، تنظیمات، تقویم و صفحه‌بندی. جست‌وجوی فارسی/لاتین، کیبورد، وضعیت خالی و اعتبارسنجی فیلد ضروری پشتیبانی می‌شود. برای ترک فرم دارای تغییرات ذخیره‌نشده از لینک‌ها یا تغییر فضای کاری، پیام تأیید نمایش داده می‌شود.

## داده‌ها و API آزمایشی

این پروژه رابط کاربردی با **API آزمایشی داخلی Next.js** است؛ اتصال به سرویس حسابداری بیرونی ندارد. در اولین درخواست، داده‌های نمونهٔ دو شرکت، شعبه‌ها، دو سال مالی، محصولات، اشخاص و اسناد ایجاد می‌شوند.

داده‌ها در `.data/taraz.json` ذخیره می‌شوند و پس از راه‌اندازی مجدد باقی می‌مانند. نوشتن فایل با صف و جایگزینی اتمیک در یک پردازش سرور انجام می‌شود. برای انتقال به API واقعی، فراخوانی‌های `api` در `src/components/provider.tsx` و Route Handler در `src/app/api/[...path]/route.ts` نقاط اتصال اصلی هستند.

| مسیر                        | کاربرد                                                              |
| --------------------------- | ------------------------------------------------------------------- |
| `POST /api/auth`            | ورود با ایمیل و رمز                                                 |
| `DELETE /api/auth`          | خروج                                                                |
| `GET /api/bootstrap`        | کاربر، شرکت‌ها، شعبه‌ها، سال مالی، تنظیمات و اطلاعات انتخابی فرم‌ها |
| `GET /api/{module}`         | فهرست رکوردها                                                       |
| `POST /api/{module}`        | ایجاد                                                               |
| `GET /api/{module}/{id}`    | جزئیات                                                              |
| `PATCH /api/{module}/{id}`  | ویرایش یا تغییر وضعیت                                               |
| `DELETE /api/{module}/{id}` | حذف رکورد مجاز                                                      |
| `GET /api/dashboard`        | شاخص‌ها و نمودارهای محاسبه‌شده                                      |
| `GET /api/reports/{report}` | گزارش محاسبه‌شده                                                    |
| `GET/PATCH /api/settings`   | تنظیمات شرکت                                                        |
| `GET /api/activity`         | فعالیت‌های ثبت‌شده                                                  |

پارامترهای `companyId`، `branchId` و `yearId` محدودهٔ درخواست را مشخص می‌کنند. `branchId=all` تمام شعبه‌ها را شامل می‌شود. گزارش‌ها فیلتر `from` و `to` با تاریخ ISO دارند؛ دفتر کل `accountId` را نیز می‌پذیرد. اطلاعات پایهٔ هر شرکت در شعب و دوره‌ها مشترک‌اند؛ اسناد عملیاتی بر اساس شعبه و سال مالی فیلتر می‌شوند.

## آزمایش یک جریان کامل

1. با مدیر وارد شوید و شرکت، شعبه و سال مالی را انتخاب کنید.
2. یک مشتری و در صورت نیاز کالا ایجاد کنید. موجودی افتتاحیه یا رسید کالا را در گردش موجودی ثبت و تأیید کنید.
3. فاکتور فروش بسازید؛ اقلام، تعداد، قیمت، تخفیف و مالیات را تغییر دهید و محاسبات زنده را ببینید.
4. فاکتور را تأیید کنید. موجودی و ثبت‌های مالی مرتبط تغییر می‌کنند.
5. از جزئیات فاکتور، «ثبت دریافت» را بزنید. اطلاعات فاکتور از قبل پر شده است. با تأیید دریافت، ماندهٔ فاکتور کاهش می‌یابد.
6. گزارش موجودی، دفتر کل، تراز آزمایشی و سود و زیان را بررسی کنید.
7. برای ویرایش سند تأییدشده، ابتدا آن را به پیش‌نویس برگردانید. اگر تسویهٔ مرتبط دارد، ابتدا تسویه را لغو کنید. API ثبت نامتوازن، موجودی ناکافی، ارجاع به شرکت دیگر و ثبت در سال بسته را رد می‌کند.

چک با وضعیت وصول‌شده، حقوق با تأیید یا پرداخت، تولید با تکمیل و سایر اسناد مالی با تأیید روی محاسبات اثر می‌گذارند. لغو سند، اثر آن را از محاسبات جاری برمی‌دارد. فرمول ساخت هنگام تکمیل تولید برای مصرف مواد و ورود محصول استفاده می‌شود.

## مفروضات محیط آزمایشی

- نرخ‌های اولیه ارز و مالیات نمونه‌اند و از تنظیمات و بخش ارزها تغییر می‌کنند؛ اتصال به نرخ زنده یا سامانهٔ مالیاتی وجود ندارد.
- تومان مبنای دفاتر است. فاکتورها از تومان، ریال، دلار، یورو و درهم پشتیبانی می‌کنند و نرخ تبدیل هر سند ذخیره می‌شود. تراکنش بانکی باید هم‌ارز حساب باشد. انتقال وجه بین حساب‌های هم‌ارز انجام می‌شود.
- موجودی و بهای تمام‌شدهٔ کالا از قیمت خرید تعریف‌شده استفاده می‌کند؛ حقوق شامل مقادیر قابل‌ورود مزایا، بیمه، مالیات و کسورات است. این محاسبات برای آزمایش تعاملات رابط هستند.
- استهلاک به روش خط مستقیم محاسبه می‌شود. موجودی افتتاحیهٔ کالا، بانک و دارایی‌های نمونه در برابر سرمایه ثبت می‌شود.
- بستن سال مالی، ثبت یا تغییر اسناد آن دوره را محدود می‌کند. انتقال خودکار مانده‌ها به سال بعد و اتصال به سامانه‌های بیرونی در این API آزمایشی وجود ندارد.
- ذخیره‌سازی فایل برای اجرای محلی و یک پردازش سرور در نظر گرفته شده است. برای استفاده عملیاتی، لایهٔ داده و منطق مالی باید به سرویس حسابداری واقعی متصل شوند.

    domain.ts                     محاسبات نمونه
    reports.ts                    محاسبهٔ گزارش‌ها و داشبورد
    server.ts                     اعتبارسنجی و کنترل دسترسی
    seed.ts                       داده‌های اولیه
    store.ts                      ذخیره‌سازی محلی
docs/
  BACKEND-IMPLEMENTATION.md        معماری، قرارداد و مراحل ساخت بک‌اند
  FRONTEND-COVERAGE.md             دامنه و شواهد پوشش رابط
tests/
  domain.test.mjs                  تست محاسبات و جداسازی داده‌ها

## بررسی و تست

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

تست یکپارچه پس از بیلد، سرور تولیدی مجزایی روی پورت ۳۱۰۰ اجرا می‌کند و داده‌ها را در `.data-test/` می‌نویسد؛ داده‌های اصلی تغییر نمی‌کنند. برای تست مرورگر به Microsoft Edge نصب‌شده نیاز دارد. برای استفاده از Chromium یا مرورگر دیگر، `channel` را در فایل تست تغییر دهید.

```bash
npm run format
```

برای تغییر محل ذخیره‌سازی، متغیر محیطی `TARAZ_DATA_DIR` قابل تنظیم است.
